# 各系统部署与升级

[中文](部署指南.md) | [English](en/deployment.md)

普通用户推荐下载Releases中的发行ZIP；开发者使用Git克隆。工具是本机应用和stdio MCP服务，不需要开放HTTP端口，也不要求Docker、管理员账号或作者的私人基础设施。

## 选择部署方式

| 场景 | 推荐方式 | 原因 |
| --- | --- | --- |
| 经办人与个人AI代理 | 发行ZIP＋一键安装 | 运行时隔离、带文件SHA清单、便于保留旧版 |
| 贡献代码或修改单位适配 | Git克隆＋同一安装器 | 源码可编辑，CI复用公开测试 |
| Linux材料处理机 | 本地安装、通过进程调用CLI/MCP | 无桌面依赖；不启用财务浏览器 |
| 企业托管/容器 | 自行封装CLI并管理资料卷与身份 | 暂无已验收的官方容器镜像或公网MCP服务 |

当前采用uv管理独立Python的部署思路，参考[uv官方Python安装说明](https://docs.astral.sh/uv/guides/install-python/)；不要求用户先手工装一套Python。公开CI在三个操作系统上重跑安装，采用[GitHub Actions的Python环境工具](https://github.com/actions/setup-python)准备开发测试环境。服务式、容器式部署不能直接复用桌面浏览器会话，因此不作为第一版默认入口。

## 系统前提

| 系统 | 已提供启动器目标 | 必需系统工具 | 说明 |
| --- | --- | --- | --- |
| macOS | Apple Silicon、Intel | 系统sh、curl、unzip、shasum | 推荐仍受系统厂商支持的版本 |
| Windows | x64、ARM64 | 系统Windows PowerShell、.NET ZIP、HTTPS下载 | 推荐Windows 11；受管设备遵循本单位脚本策略 |
| Linux | x86_64、aarch64 | sh、curl、unzip、awk、sha256sum或shasum | glibc发行版；Alpine/musl未验收 |

“提供下载目标”不等于所有架构实测通过。每版公开CI和已知限制见[验证说明](验证说明.md)。OCR依赖是否提供当前架构的轮子，由锁定的上游包决定；ARM64 Windows未验证，遇到缺轮子会明确失败，不自动改用别的模型。

Ubuntu/Debian最小系统缺少基础工具时，由系统管理员安装：

```sh
sudo apt-get update
sudo apt-get install curl unzip ca-certificates libgl1 libglib2.0-0
```

后两个库供可选OpenCV/OCR使用；有些较新发行版将glib包命名为`libglib2.0-0t64`，按发行版提示选择。普通用户无sudo权限时，请管理员准备依赖，不将系统库塞进用户Python目录。

## 首次安装

1. 从Releases下载发行ZIP和`SHA256SUMS`，核对文件SHA。macOS用`shasum -a 256 文件.zip`，Linux用`sha256sum 文件.zip`，Windows PowerShell用`Get-FileHash 文件.zip -Algorithm SHA256`。
2. 解压到长期可写的位置，例如`D:\Tools\ustc-reimbursement`；避开系统目录和浏览器临时下载解包目录。路径可以包含空格和中文，终端中用引号包住。
3. macOS/Linux执行`sh install.sh`；Windows执行`install.cmd`。在PowerShell中使用`./install.cmd`。
4. 查看终端返回的`ok`和报告路径，打开HTML报告。基础检查失败时先修复，不跳过失败继续办财务。
5. 按[用户指南](用户指南.md)配置私人规则和资料范围，再导入MCP配置或让AI读取AGENTS.md。

没有Python也可安装。Python、uv、缓存和依赖都落在工具的`.local/`。首次需要访问`files.pythonhosted.org`、`pypi.org`及Python独立构建的GitHub下载源。依赖安装使用冻结版本；网络受限时先让管理员放行或在有权限的网络完成安装，不关闭TLS校验。

安装器隔离用户的Python/pip/uv配置，避免误用其他项目镜像或环境；它不默认支持组织私有包镜像。需要自定义企业代理、证书或离线包源时，应增加明确的部署配置并验收，不把密码写进脚本。

独立OCR安装：

```sh
sh install.sh --with-ocr
```

Windows为`install.cmd --with-ocr`。这会下载CPU依赖和模型并用合成页实测；实际报销材料不会上传外部服务。远程OCR另行配置，不是安装器默认行为。

## Git源码安装

```sh
git clone https://github.com/Rtiming/ustc-reimbursement.git
cd ustc-reimbursement
sh install.sh
```

Windows在最后一步运行`install.cmd`。Git检出自检按当前允许清单检查源码和派生入口，标记为`current_git_checkout`；发行ZIP按冻结MANIFEST检查，标记为`release_manifest`。两种来源不会混称为相同版本证据。GitHub自动生成的Source code ZIP没有`.git`或发行MANIFEST，应改用发行附件，或自行构建发行包。

## MCP与命令调用

生成的`.local/client-configs/mcp.json`包含当前设备的绝对路径。导入现有客户端时只合并这一项，保留其他服务；Codex等客户端的额外配置片段也在同目录。工具不自动改全局AI配置。stdio MCP由客户端启动，不监听网络；客户端需要能运行本机进程。

安装后统一CLI为`sh tools/reimbursement.sh`（Windows为`tools\reimbursement.cmd`），它使用本项目环境。`assistant.py call --input 请求文件`读取JSON；参数合同见`mcp/tool_catalog.json`。不要向工具开放整个主目录，只给明确的资料根。

## 自检、升级和迁移

自检运行`sh install.sh --check`或`install.cmd --check`，不安装依赖、不修改规则；需要已完成一次安装。报告中的可选能力缺失不影响相互独立的离线材料能力。安装失败保留当前报告目录的`install.log`，修复后重跑同一入口可继续。

升级先停止当前工具的活动任务，保留旧目录及回执，在新目录安装新版本。资料根可继续指向原资料目录；案件登记`cases/`和任务状态`.local/assistant_jobs/`要按案件README及工具返回的恢复说明迁移，不能把旧Python环境或整个`.local/`覆盖过去。仍有未知写结果的任务必须先在旧版恢复原任务，不在新版换号重试。

换电脑时重新安装依赖、生成MCP路径并本人登录浏览器；复制已授权的案件/规范/原件，保持来源SHA。不要搬账号会话数据库。卸载前先保留资料、案件与回执，再移除专属工具目录；如装过浏览器桥，先用桥自己的卸载入口解除本机注册。

## 常见问题

| 提示 | 处理 |
| --- | --- |
| 缺少curl/unzip/SHA命令 | 安装系统前提，再重跑；不跳过校验 |
| PowerShell脚本被禁止 | 使用组织允许的运行方式；安装器不修改ExecutionPolicy |
| 下载失败/证书失败 | 检查网络、系统时间和证书，保留日志；不使用不安全下载参数 |
| 缺`libGL.so.1`或glib | 按Linux前提安装OpenCV系统库 |
| 包成员SHA变化 | 发行目录被修改或下载损坏；重新下载并核对。开发改动在Git检出完成 |
| 公开入口与源码不一致 | 按CONTRIBUTING同步派生入口，再测试 |
| 未配置规则/外部提供方 | 这是待配置状态，不能解释为材料齐全或OCR已运行 |
| 财务网页不可用 | 先确认平台支持，再按用户指南接线；离线自检不证明登录和审批可用 |

Windows、Linux与macOS共用业务接口与资料结构，平台差异集中在安装器、路径和浏览器适配器。

## 声明式部署与预览

复制`distribution/deployment.example.json`为自己的部署文件，可补充本机绝对路径`data_dir`。固定字段只有schema、data_dir、profile_id、title、mode、with_ocr；不接收密码、命令或任意环境变量。命令行与文件冲突时明确拒绝。

```sh
sh install.sh --config /绝对路径/deployment.local.json --plan
sh install.sh --config /绝对路径/deployment.local.json
sh install.sh --config /绝对路径/deployment.local.json --check
```

Windows换成`install.cmd`。`--plan`仅读配置和源码清单，不创建资料/环境、联网或运行探针；需要已有Python3.11+或已安装环境，无解释器时不会为预览下载。`--check`放在任意参数位置均不触发安装。成功安装后`.local/installation.json`中的deployed_source绑定版本、源码树SHA及成功回执；失败不推进该指纹，自检发现源码变化要求重新核验。

## 用户更新操作

```sh
sh update.sh
sh update.sh --install
```

Windows使用`update.cmd`、`update.cmd --install`。第一条只查询本仓库公开Releases；第二条按SHA256SUMS、GitHub附件digest（若提供）及包内MANIFEST逐文件SHA验证，再在相邻的新版本目录执行安装与合成自检。测试版默认跟随测试渠道，正式版默认仅正式渠道；可用`--channel stable`或`--channel preview`覆盖，`--version v版本`准备指定版，`--destination 绝对路径`指定新目录，`--download`只下载核验。

更新保留旧工具和全部任务现场，复用已绑定资料根及专项；原本启用本机OCR时继续显式安装本机OCR。相同已验目标可接续，其他已有目录拒绝覆盖。新目录验收通过才返回installed及新的MCP片段；随后合并片段并重启该服务。安装失败查新目录`.local/update-install.log`；原目录继续可用。

案件、历史回执、财务登录和其他私人集成没有自动迁移。旧案/未知任务沿旧目录恢复；新目录用于新工作，迁移已有案件前逐案核对恢复合同。资料根若在旧工具目录内，须继续保留该目录。更新不是原地替换，也没有自动切换或自动回滚运行环境；回到旧版直接使用保留的旧入口。旧版没有update入口时，首次仍从Releases核SHA下载本版，后续使用上述命令。

发行查询协议参考[GitHub Releases API](https://docs.github.com/en/rest/releases/releases)。网络、包完整性、本机安装和真实财务办理分别验收。
