# 材料、打印与可选能力

先按`capabilities(intent="materials")`返回的下一步办理，选定本机案件和资料根。准确JSON参数来自`mcp/tool_catalog.json`；`guide(topic="intake")`给出统一收件请求。这里是公开版能力说明，不是任何单位的已确认制度。

## 材料与规则

原件以SHA登记，压缩包逐层展开并保留来源。纸质原件、扫描件、电子原件和OCR文字分别记录。票据、费用、付款证明及最终报销收款关系分别核对，不根据同名同额自动合并。默认只附已有付款材料，缺项明确列出；本单位另有强制要求时登记到相应专项规则。

私人规范库通过standards_init、standards_add_profile、standards_change维护，先预览再保存并回读。新安装的共用规则和项目规则为空；`data/material_rules.json`初始需要确认，不会把未配置状态报告成材料齐全。具体用法见[模式与场景](模式与场景.md)和[用户指南](用户指南.md)。

材料整理后的清单依次列人员及拟打款、报销材料及明细、纸质材料。仅将已有电子材料整理为连续A4单面PDF，每页独占一张纸，横竖按材料选择；纸质只登记，不打印其扫描件或占位页。附加标头、页眉页脚默认关闭。工具入口`tools/print_packet.py --help`；执行前以本案清单明确选择原件和顺序，产物不替代财务系统原生导出。

OCR先调用ocr_status，再从本案已完成收件job选择material_ocr；识别结果接回同一材料清单，文字仍为候选。配置与恢复见[OCR统一流程](OCR统一流程.md)。

## 官方活动审批表

工具含`tools/activity_form.py`的填表实现，但公开包不包含学校二进制母版、签字、盖章或历史填写案例。先从本单位取得有效母版并登记版式、字段、版本和来源，再由维护者配置对应适配器。当前实现含特定母版的字段映射，不能直接套到任意表格；未提供匹配母版时保持缺项，不能用合成表代替官方批准。先查看`python reimburse.py activity --help`，只做草稿并核对字段和渲染；签字盖章及审批状态不能由程序生成或推断。

## 总账与导出

统一总账模型位于tools/reimbursement_ledger.py，数据按人员、费用、票据、材料及关联关系分别保存，费用主键决定金额计数。金额以整数分或null表达，票号、学号等标识保持字符串。票面金额、申请金额、拟打款与实际到账分别记录；历史观察保留采集时间。

ledger_query与ledger_trace可读取已经登记的总账结果。批量建账使用显式配置的远程提供方；公开包提供工具适配器，不部署维护者的远程服务。表格成品的专有创作运行时也未包含；没有提供方时保留结构化数据和具体缺项，不能声称已经输出工作簿。为新的服务实现适配器时保持输入快照、源码版本、输出SHA和验收回执，不将任意命令暴露为MCP方法。
