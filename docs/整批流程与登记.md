# 从新安装到整批财务流程

[中文](整批流程与登记.md) | [English](en/batch-workflow.md)

本页是0.5系列候选入口。Windows和macOS复用同一工作页、案件、请求和回执合同；发布前仍须完成对应设备的真实业务验收。Linux只做离线资料处理。验证码由本人填写，工具不读取验证码，也不将其他人的审批角色自动纳入流程。

## 1. 安装与私人配置

解压发行附件，在Windows运行`install.cmd`，macOS运行`sh install.sh`。安装、自检与MCP配置见[部署指南](部署指南.md)。新资料库中的规则为空，不能继承作者的经费、身份和限额。规则使用安装记录中的`library_root`，填写、规划和批次检查共用这个位置。

MCP和JSON使用同一接口；先调用capabilities。JSON请求保存为UTF-8文件，通过`tools\reimbursement.cmd call --input 请求绝对路径`执行；macOS换成`sh tools/reimbursement.sh`。完整字段以`mcp/tool_catalog.json`为准。

## 2. 接通Windows现有Edge

先在Windows正常登录桌面并保持Edge打开。工具只安装本项目固定扩展，不启动其他账号、不复制浏览器资料，也不修改浏览器安全策略。

```json
{"method":"bridge","params":{"action":"install"}}
```

这是预览。返回`registration_sha256`及是否存在旧登记；核对后使用同一SHA和稳定请求号：

```json
{"method":"bridge","params":{"action":"install","execute":true,"request_id":"edge-setup-01","expected_registration_sha256":"填入刚回读的SHA"}}
```

Windows安装器通过当前已登录用户的交互令牌运行固定安装程序，不保存密码、不提升权限。SSH处于Session 0时，也不把那里的空桌面当成用户桌面。结果查询：

```json
{"method":"bridge","params":{"action":"installation-result","request_id":"edge-setup-01"}}
```

结果查询不会再次运行安装；会回收已结束且身份完全匹配的本次一次性安装任务，保留安装回执。未知结果沿原请求检查。旧主机仍占锁、有未结束请求、登记或SHA变化时拒绝迁移。迁移只处理同名本项目主机，旧登记保存在新工具`.local/edge-bridge/previous-registration.json`；原账号和登录数据库不动。

当前Edge受组织策略限制、用户桌面未登录或安装窗口无法唯一识别时，保留缺项，不关闭策略。安装完成后再`bridge status`和`bridge inventory`，核当前扩展、连接命名空间及工作页。安装成功不代表已经登录财务或已经批准单据。

本人在财务页面登录。新登记流程默认`session_only`，不会要求作者的密码库；统一access也支持显式`session_only:true`。工具只复用当前会话，当前账号必须与本批expected_userid相同。

## 3. 准备逐案输入

先通过new_case、材料收件、规范选择与prepare_batch_file准备逐案计划，再沿原有上传、选票、建单入口取得真实单号及原生票据绑定。批次导航案件单独创建，不绑定财务单号。单据案件用cases→overview核对。

登记入口不会编造财务单号、票GUID、经费候选、审批人或保存证据。当前准备流程要求每个案件对应一张已拆分form、明确无合同和自行打印；未知值不默认为否。一次规划含多张form时先按实际拆分逐案规划。不要把整批规划JSON直接改名当办理索引。

每案plan_path应是prepare_batch_file保存的正式JSON，带归一化输入路径及SHA、专项版本、金额、摘要和确认日期。案件字段须与计划一致。准备授权还需要每项经费的已确认单位审批人，来源明确到当前案件。

## 4. 预览与登记批次

下例只是结构，必须换成本机已核案件和路径；示例不授予财务写入权限。

```json
{
  "method":"register_workflow",
  "params":{
    "case_id":"my_batch",
    "output_dir":"D:/Reimbursement/materials/batch-registration-v1",
    "request":{
      "schema":"ustc-workflow-registration-v1",
      "scenario":"my_project",
      "expected_userid":"本人实际财务账号",
      "source":"本次案件范围与授权的确认位置",
      "authorize_prepare":false,
      "authorize_approve":false,
      "show_verification_interface":true,
      "department_approvers":[],
      "documents":[{"case_id":"actual_document","plan_path":"D:/Reimbursement/materials/actual-document-plan.json"}],
      "delivery":{
        "export_root":"D:/Reimbursement/materials/system-exports",
        "download_directory":"本人Edge实际下载目录的绝对路径",
        "format":"EXCEL",
        "filename_separator":"_"
      }
    }
  }
}
```

源文件、目标目录和案件变更都会使预览SHA失效。核对预览后给params增加`execute:true`与`expected_preview_sha256`等于刚返回的值。工具生成索引、授权清单、两类导出计划和冻结登记引用，不覆盖已有版本。

准备与本人批准分别授权。`authorize_prepare:true`只用于本次已明确允许填写和准备待审的案件；`authorize_approve:true`还须有当前精确案件集合的本人批准安排。单位审批人每项为`project/id/name/source`，项目须对应本案经费；未明确时不猜。

登记成功仅表示本地配置完成。没有准备回执时不会生成可执行的批准清单；ready取得全部真实准备证据后，工具才按原授权生成新版本清单并回读。也可给每案提供本工具原job/artifact/SHA组成的preparation_receipt，登记前逐项核验其真实原生状态。

## 5. 分阶段调用

```json
{"method":"workflow","params":{"case_id":"my_batch","phase":"status"}}
```

| phase | 用途 | 执行前条件 |
| --- | --- | --- |
| fill | 填写并独立回读已有草稿 | 当前计划、原件/选票、字段和准备授权完整 |
| ready | 准备到本人待审 | 真实账号、单号、单位审批人及逐单原生回读 |
| approve | 本人同意与验证码后接续 | 真实准备回执＋本批明确批准授权 |
| export-system | 查看明细PDF原字节归档 | 确认日期、序号、摘要、输出根 |
| export-list | 原生列表导出 | 精确单号范围、格式、实际下载目录 |
| finish | 批准后依次完成两类导出 | 批准、PDF、列表三段输入预检均通过 |

每个阶段先用`execute:false`预览，已授权后同一阶段改为true。MCP为reimbursement_workflow；长批次也可运行`tools\reimbursement.cmd workflow --case-id my_batch --phase ready --execute`，保留原进程及回执。不要因客户端超时换一个批次重新执行。

验证码停点返回verification_required；登记中明确`show_verification_interface:true`才显示原绑定页面，默认保持静默。本人填写后继续同一batch/approve阶段，工具先独立回读：原生回调已经批准时记录结果，不再点同意。页面丢失、连接身份变化或原金融动作未知时保持停止，不拿新页面冒充原现场。

查看明细PDF和列表导出始终独立记录。仅按既定映射重命名归档，不重复核对PDF正文、金额、页数或版面。缺文件、下载未完成、重名冲突及搬运失败保留原任务。没有配置列表导出的新登记不能把finish说成完整交付。

## 6. 验收与升级

新用户验收要分别覆盖：独立安装与规则配置、另一AI实际调用、桥连接、真实登录及案件、人工验证码、逐单状态回读、两类导出、原请求恢复与完成结果复用。合成测试不能代替真实审批；已完成单据不能重复批准作测速。

升级使用新目录并保留旧版/回执。对本次新目录重新安装依赖与桥接线，不复制旧.local或账号数据库。源码、安装与真实业务证据分别保存，未验收的平台或动作不能标成可用发布。
