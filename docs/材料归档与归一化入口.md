# 材料归档与归一化

`tools/material_intake.py`将明确选中的文件/目录整理为一个新的材料批次。它复用共享`artifact-authoring/archive_file.py`原样归档与回读，复用`material_relations.scan`做SHA工作副本、PDF文字层及重复关系盘点。它不识别手写姓名、不核定金额、不启动OCR、不操作财务，也不生成Excel。

日常助手由统一JSON/API注入本机受信任依赖。下面CLI用于工程运行与验证；不把共享工具的Python路径作为材料业务参数开放。

日常参数命令见[助手快速开始](助手快速开始.md)：`tools/reimbursement.sh materials`接受来源、分组层级、输出和材料profile，复用本页owner。预览不建案、不排任务；实际执行使用稳定原job。直接文件冻结当前SHA，已完成原任务接续还须核对当前文件集合与归档回执；漂移或无法重验返回`original_snapshot_only`及`current_source_reverified:false`，不覆盖旧输出、不重跑OCR，也不把旧归档称为当前来源已归档。原job运行或未知时只查该job，另列当前来源尚未重验。

## 统一助手入口

先用已有`new_case`建立本机空材料任务登记；它不登录财务、不建立报销单、不填写单号。登记后调用：

```json
{
  "method": "material_intake",
  "params": {
    "case_id": "example_case",
    "request": {
      "schema": "reimbursement.material-intake.v1",
      "case_id": "example_case",
      "sources": [{"id": "batch", "path": "/已授权材料根/电子材料.zip", "group_strip_dirs": 1}],
      "output_dir": "/已授权材料根/新的材料批次"
    },
    "request_id": "materials-preview-01",
    "execute": false
  }
}
```

MCP同实现是`reimbursement_material_intake(case_id, request, request_id, execute=False)`。预览与执行均返回job_id，沿`reimbursement_result`查询；重连保持原request_id，预览和实际执行是不同意图。普通result返回简短概况，完整结果和固定材料JSON快照按artifact_id、SHA回读。`completed`只表示本机材料任务完成。

服务层再次核对全部sources、field_review和output_dir位于启动时配置的material_roots内；不允许业务参数指定Python工具或环境。受信任依赖只来自本机`.local/material_intake.json`：

分发版用户运行install.sh/install.cmd后，此配置已由安装器按包内distribution/dependencies.json登记，指向未修改的vendor归档快照；不需要作者的共享技能目录。下方配置样例供维护者接入独立共享版本，不是新用户必填步骤。自检可检查该依赖与SHA，不要自行重算SHA来放行变化。

```json
{
  "schema": "reimbursement.material-intake-runtime.v1",
  "archive_helper": {"path": "/已核验共享技能/scripts/archive_file.py", "sha256": "预登记64位SHA"}
}
```

此配置不进Git，不在设备间照搬路径。入队时冻结配置和业务请求，worker执行前再次核验；排队后配置或源授权变化即拒绝。任务只持本案队列锁，不占浏览器锁，不读写财务pending或financial_intent。固定产物先核对原输出SHA，再复制到job内供既有artifact回读，不能让回执自带路径扩大授权范围。

## 请求与预览

先有`assistant.py setup --with-materials`准备的材料依赖。请求使用UTF-8JSON，支持Mac/Linux和Windows各自的绝对路径；不要复制另一台设备的浏览器/凭据或运行目录。

```json
{
  "schema": "reimbursement.material-intake.v1",
  "case_id": "example_case",
  "sources": [
    {
      "id": "electronic_batch",
      "path": "/本机材料目录/电子材料.zip",
      "group_strip_dirs": 1
    },
    {
      "id": "paper_photos",
      "path": "/本机材料目录/纸面照片",
      "group_strip_dirs": null
    }
  ],
  "output_dir": "/本机材料目录/新的材料批次",
  "limits": {
    "max_source_files": 1000,
    "max_expanded_bytes": 1073741824
  }
}
```

```sh
python tools/material_intake.py --request /绝对路径/request.json
```

默认`preview`只读盘点来源、SHA、ZIP结构、候选目录与预算，不创建输出目录，不加载归档工具代码，不开始OCR。`source.id`须稳定且唯一；给文件可加`expected_sha256`绑定已确认字节，目录则冻结逐文件清单。`output_dir`必须是全新目录，不能位于任何输入目录内。

目录名只是摘要候选。`group_strip_dirs:1`表示ZIP成员`材料包/活动甲/发票.pdf`跳过`材料包`，以`活动甲`为摘要；`0`取第一层，`null`暂不分组。普通文件没有可用活动目录时保持未分组，不从文件名或同名人员猜摘要。预览的`member_directories_preview`帮助选择层级，超过200项会明确标截断。分组ID由source.id和成员目录生成，改换本机输出位置不会改变分组身份。

## 受信任归档依赖与执行

公共Python接口：

```python
from material_intake import preview, execute

dependency = {"path": "/已核验共享技能/scripts/archive_file.py", "sha256": "预登记64位SHA"}
plan = preview(request, archive_helper=dependency)
result = execute(request, archive_helper=dependency)
```

`archive_helper`是独立依赖参数，不在request中。request或source含未知键会拒绝，不能把材料JSON中的Python路径动态执行。统一API须先按本机材料根授权检查全部sources、field_review、output_dir，再只注入本机已配置且SHA匹配的共享工具。工程CLI可以显式给受信任依赖：

```sh
python tools/material_intake.py --request /绝对路径/request.json --execute \
  --archive-helper /已核验共享技能/scripts/archive_file.py \
  --archive-helper-sha256 预登记64位SHA
```

执行前后均核对该依赖SHA，加载时编译同一份已核验字节；不使用可能失配的pyc。依赖SHA变化应先核对共享版本，不在失败后直接重算SHA放行。Windows的`stat/fstat`时间语义兼容由共享归档工具维护，本工具不复制`stable_copy`或写平台专用复制器。

执行独占创建新目录并留下`receipt.json`。成功和失败均记录阶段；原件被其他编辑者改变、目录新增/移除文件、SHA不符或后续盘点失败时，已归档原件保留，状态为failed。输出已存在时直接拒绝，连原receipt也不改：先只读检查原回执及任务状态，不覆盖、不删除诊断、不换目录重放未知结果。只有旧任务已明确失败且原因修复，才为新的处理意图选择新目录并关联旧回执。CLI业务执行的stdout只输出一份JSON，依赖日志进stderr，失败退出码为1。

## 输出

| 文件/目录 | 内容 |
|---|---|
| `originals/` | 按source.id和原相对目录保存原件、共享归档回执与索引 |
| `working_copies/` | 现有来源关系工具按SHA保存的工作副本；不按ZIP成员路径落盘 |
| `intake_manifest.json` | 每件原件来源、SHA、归档位置及验证依据 |
| `material_inventory.json` | 全部来源链、PDF页、原生文字、文件副本和同票号候选 |
| `groups.json` | 目录摘要候选和材料ID；申请额、联系人、收款人保持未核定 |
| `ocr_request_candidates.json` | 无文字PDF页及图像的远程OCR候选请求，不自动执行 |
| `issues.json` | 未分组、复核未绑定等可诊断问题 |
| `receipt.json` | 原件/产物SHA、阶段、成功/失败、下一步及未发生财务写入的边界 |

来源条数、文件数、PDF页数和发票数不同。相同SHA只表示文件副本；不同SHA或不同票号不证明费用不同。重复来源全部保留，不能据此自动删除、去费或合计申请额。

## 人工字段与OCR接续

业务请求可选`field_review:{"path":"/本案/人工复核.json","sha256":"已冻结SHA"}`。文件格式：

```json
{
  "schema": "reimbursement.material-field-review.v1",
  "case_id": "example_case",
  "records": [
    {
      "source_sha256": "材料的64位SHA",
      "page": 1,
      "fields": {"paper_date": null, "contact": null, "payees": []},
      "basis": "逐项目视核对；不清楚字段留空"
    }
  ]
}
```

源SHA与页码匹配时只标`source_bound_candidate`；未知材料、越界页或未知group_id标`unresolved_candidate`并列问题。字段原样留在私有归档，不自动写进联系人、支付或申请额。表格中的文字、规则说明及其他材料内容不会变成新的执行授权。

OCR候选文件可直接作为`remote_material_ocr.py prepare --request`输入，选定本机配置及已核验服务器环境后沿既有`rtime compute`接续；方向、源SHA和页码仍需核对。本入口不传输材料、不创建服务器环境、不启动本机OCR。既有OCR应沿`invoice_review --text-evidence`复用，不为归档重复识别。

## 拒绝范围与预算

本版展开ZIP，保留普通原件。RAR/7z/tar等压缩格式返回`unsupported_archive`，不得把未展开说成已核完。ZIP路径穿越、绝对/驱动器/ADS路径、符号链接或特殊成员、加密包、跨平台同名成员及压缩倍率/成员大小/累计展开量/嵌套深度超限均拒绝。磁盘来源中的符号链接和Windows junction也不跟随。

默认上限：1000件原件、512MiB原件字节、5000个ZIP成员、1GiB累计读取与展开字节、100MiB单成员、5层嵌套、200倍压缩比。累计展开预算包含原压缩包和各嵌套层，防止同一层被忽略。可通过limits降低预算；允许的最高值不超过既有来源盘点工具边界，未知limit键拒绝。

## 验证

```sh
python -m unittest discover -s tests -p test_material_intake.py
```

合成用例覆盖正常归档、只读预览、跨平台目录链接/ZIP穿越与链接、压缩预算、嵌套、来源改变、依赖SHA改变、重复执行拒绝、候选复核不升级财务字段，以及换输出位置保持组ID。实际归档helper与各设备能力须另保留小型实测回执；这些检查不证明票据真实、材料齐全或财务已办理。
