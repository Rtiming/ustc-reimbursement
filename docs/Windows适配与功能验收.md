# Windows适配与功能验收

Windows与macOS共用业务参数、任务、回执和固定HTTP接口。Windows使用Edge Native Messaging；Linux运行离线材料功能。能力以`capabilities`、准确schema及本版验收结果为准。

## 现场改动如何纳入主线

本次对照0.5.0-beta.2原始MANIFEST逐文件核对Windows现场9个变更文件，并审阅部署与操作记录。仅移植通用修复；个人账号、材料、专项规则、审批人和一次性脚本留在原设备。记录中的旧现场成功不等于新版已完成同一真实业务。

| 现场问题或改动 | 正式处理与入口 |
| --- | --- |
| 旧CLI将Windows一律当作离线平台 | `tabs`和发票只读使用实际后端校验；写业务继续走统一HTTP接口，不恢复已停用的旧点击写路径 |
| PowerShell请求文件带BOM、内联JSON引号丢失 | `assistant.py call --input`接受带/不带BOM的UTF-8文件；请求用文件传入，路径有空格时加引号 |
| 证明人工号查询只返回纯姓名 | `basic`按已确认工号查询并核对姓名，兼容工号/姓名/单位格式；不从同名人员中猜工号 |
| 相同经费编码出现不同负责人 | `funding[].owner_name`精确匹配原生负责人；冻结编码、grant_id和负责人并在保存前重查；仍不唯一就停止 |
| 未分配科目的金额格subject为`*` | `expense_amount`接受这一确切原生值；仍绑定分组、单号、本人、原票及减报依据，不接受任意表达式 |
| node=508把可编辑草稿误记为本人审核 | 旧回读还须观察到本人同意控件；HTTP路径按完整单据状态及原生流程实例判定 |
| 内置Administrator的SDDL别名使安全管道失效 | 0.6主线已按实际ACE和SID核对；保留RID500回归，拒绝额外主体、继承及不同权限 |
| 大文件上传超过Native Messaging单帧限制 | 正式`invoice upload`用固定HTTP分块上传和原批次独立回读；未知结果只`upload-resume`，不清pending再传 |
| 现场删除OCR异常核对、关闭材料规则 | 不移入公共默认；用`verify_invoice`登记原件核对，私人规范逐案确认。上传就绪与审核通过分开 |
| 固定审批人、打印和辅助证据一律选否 | 不复制个人默认。审批人来自本案与原生候选；打印/合同/辅助证据由本案提交计划和独立回读控制 |
| 为审批别人的单放开unbound绑定 | 使用已有`finance_connection approvals → approver_batch`，冻结完整审批清单、节点、金额及授权；不借申请人接口绕过绑定 |
| 修改/撤单脚本放开确认按钮 | 使用已有固定HTTP撤单和草稿恢复；原状态、身份、依据和独立回读仍必需。未知结果不重做建单 |
| 无发票的薪酬单、减报与收款顺序 | 薪酬使用独立remuneration事项；日常单先建单、经费及金额调整、核对支付，再进入审核。不能用`no_invoice`跳过普通报销原件要求 |

## 功能入口与验证

| 功能域 | 当前入口 | 本版需要的验证 |
| --- | --- | --- |
| 安装、更新、升级回退、桌面工作台 | `install.cmd`、`update.cmd`、工作台维护 | 新目录精确ZIP安装及自检；保留原安装与任务 |
| 收件、去重、OCR、私人规则、核对、分单、PDF和Excel | `capabilities`、材料工作台、`case_journey` | 三系统合成原件归档、OCR、回读和成品交付 |
| 连接、门户与报销子系统 | `finance_connection`或`tabs → access` | 本机扩展连接；明确账号及tab。`finance_home`只表示门户，不能称为已进入报销子系统 |
| 上传、识别、选票、建单、恢复 | 统一`invoice`和登记workflow | 原件SHA、账号、完整票池及原请求恢复合同 |
| 基本信息、经费、分类、预算、减报、支付、说明、预审 | `stage`、`expense_amount` | 每个固定HTTP适配器的正常/拒绝/未知结果合同及独立回读 |
| 提交选项、普通承诺、单位审批人、本人同意 | `submission`及workflow | 本案授权、同号金额、节点及短信停步；不在发布验收中重办真实单据 |
| 待本人审批的他人单据 | `finance_connection approvals`、`approver_batch` | 独立审批角色、完整分页清单、授权、单次批准及回读 |
| 薪酬、医疗、行程和补贴 | 各自专用事项和能力目录 | 支持的参数与适配器分别验收；学生薪酬实现不冒称涵盖全部非在职讲课费 |
| 撤单、退回修正、正式打印、明细与原生列表导出 | 专用cancel/correction/print/export接口 | 各自状态合同、输出SHA及原任务恢复；明细PDF不代替正式打印 |
| 安全凭据、远程OCR/总账、手机采集 | 本人配置的提供方 | 可选接入独立验收；包不携带其他人的凭据或设备服务 |

公开CI从精确发行ZIP解压，在Windows、macOS、Linux运行全部已收录Python回归和Node合同、真实stdio MCP、材料归档及CPU OCR。它不连接学校账号。版本、运行链接及结果见[验证说明](验证说明.md)和相应Release。

## Windows环境与迁移

1. 完整离线包解压到可长期保留的当前用户可写目录，建议D盘；普通源码包首次安装需联网。不要从压缩包、客户端临时受限工作区或低完整性进程运行业务。
2. 若后台启动返回拒绝访问或unknown，保留job/request/pending，先查原结果。可在本人普通PowerShell中对隔离的合成安装运行`install.cmd --check`定位环境权限；移动文件本身不能证明进程完整性已改变。不要借提权或新请求重复未知任务。
3. 新目录安装不自动搬浏览器注册。先查新旧主机状态，再按安装器提供的旧登记SHA确认迁移；保留旧目录和备份。不要结束整个Edge或覆盖已连接主机来完成发布验收。
4. 门户已登录但报销子系统未就绪时，先查看当前账号和页面状态。没有未保存内容、没有pending的明确空页面才可按正式恢复入口刷新；不能把刷新当写入失败后的自动重试。
5. 规范、案件、资料根与历史回执沿各自迁移入口接续，不整目录回灌旧文件，不复制Cookie、登录库或虚拟环境。文件锁由进程持有；看到空锁文件不代表应删除。

Windows完整离线包的本机服务探测直接访问127.0.0.1，不借用户的外部HTTP代理；安装断网验证为回环地址保留直连。Node是源码开发合同测试的运行时，完整离线用户包不要求安装Node；缺少Node时对应测试明确跳过，三系统CI仍安装Node并执行这些合同。

Windows读取状态文件时可能短暂拒绝原子替换；桥在1秒预算内接续同一份冻结状态字节。持续权限错误仍停止，排他请求/意图仍禁止覆盖，登录与财务操作不重放。

状态临时文件不重复业务文件名，保留同目录排他创建与原子替换，避免普通资料路径尚未达到Windows上限时，临时后缀先让安装自检失败。
