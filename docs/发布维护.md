# 公开版维护与发布

[中文](发布维护.md) | [English](en/maintenance.md)

公开源码正本为`https://github.com/Rtiming/ustc-reimbursement`的main分支，版本使用Git标签和GitHub Releases。用户案件、私人规范及账号运行状态独立保存，永不随源码发布。

首版从声明的源码清单建立全新历史，没有导入内部历史仓库。后续公共改动通过公开分支评审；内部业务部署按公开版本升级，私人现场不能反向整仓推送。不得把内部仓库改为public来代替本流程。

## 构建

版本唯一正本为`distribution/data/distribution.json`。修改后同步公开入口，运行公开测试。构建目标须是不存在的绝对目录：

```sh
python tools/prepare_public_checkout.py --execute
python -m unittest discover -s tests -p 'test_*.py'
python tools/build_distribution.py --output-dir /绝对路径/新的发行目录 --execute
```

Windows同样使用Python入口和本机绝对路径。构建器只打包`distribution/source-files.json`中的文件，拒绝链接、路径穿越和已知私人路径，生成逐文件SHA的MANIFEST与构建回执。回执中的本机路径留在维护者本机；发布附件只上传发行ZIP和SHA256SUMS。

## 验收与发布

1. 审查实际暂存文件及将发布ZIP的成员，不能只检查.gitignore。用gitleaks的dir和git模式检查公开树及全部公开历史，开启`--redact`；疑似秘密不得出现在CI日志。
2. 在新目录解压精确发行ZIP，重新运行一键安装、自检、stdio MCP与合成收件；OCR变更还要用合成图执行真实识别。
3. 公开CI分别在macOS、Windows、Linux运行同一流程，确认实际完成。架构、财务浏览器和可选外部服务没有实测的部分要写明。
4. 创建版本标签、发布预发行版，附ZIP、SHA256SUMS、变更说明和限制。不得将测试回执中含个人路径的原文件上传。
5. 独立读回远端提交、标签、许可证与附件SHA，再从公开仓库新克隆验证。记录版本、提交、SHA与测试链接。

## 自动化范围

`.github/workflows/ci.yml`从`distribution/ci.yml`生成。工作流只需读取仓库的权限；依赖安装访问公开软件源，不需要学校账号、个人服务或仓库Secrets。它使用合成资料，输出自检结果和不含真实案件的演练回执。发布动作由维护者单独执行，不因任意PR自动上传Release。

安装器与锁文件更新时保留可复现版本，不使用浮动latest替代已验证依赖。模型SHA变化需要核来源并重新验收，不能重新签名未知模型来绕过失败。

经明确授权，可以先发布用于隔离安装、资料处理与接口试用的测试版；必须标为prerelease，并以中英文注明Windows真实财务流程尚未实测。测试版发布不等于生产可用验收，也不授权操作真实单据。
