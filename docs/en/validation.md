# Validation scope

[中文](../验证说明.md) | [English](validation.md)

Check the [Actions run](https://github.com/Rtiming/ustc-reimbursement/actions) for the exact commit. A workflow file or an uploaded archive alone is not a passing result.

The prerelease's isolated matrix covers macOS ARM64, Linux x86_64 and Windows AMD64: build a ZIP, extract into a new Unicode/space-containing path, install an independent runtime, run self-checks, Python regression, Node contracts, actual stdio MCP, synthetic intake and CPU OCR. Windows-only native-process and permission tests are explicit skips on other systems.

An independent AI has made actual CLI/JSON and stdio MCP calls on synthetic local workspaces, including registration preview/save and negative input cases. This does not certify every AI client's configuration UI or a fresh physical Windows deployment.

Windows live finance work was deferred by the user. No current acceptance claim covers real login, code entry, owner approval, live detail-PDF/list export or a five-minute batch. No real bills should be approved again merely to create a benchmark. Earlier macOS evidence applies only to the tested implementation and inputs, not automatically to later changes.

Other architectures, browser revisions, user policies and optional providers require their own qualification. OCR output is candidate text. Saved fields, owner agreement, supervisor approval, official printing, original delivery and payment need their respective evidence.

Security review and known-vulnerability scans are additional evidence with their own scope/date. They do not prove the absence of all defects. See [security](../../SECURITY.en.md) and the [review record](security-review.md).
