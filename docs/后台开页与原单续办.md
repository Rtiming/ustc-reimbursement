# 后台开页与原单续办

2026-10-17用户更正：静默是可选开关，新开页面允许按本案选择关闭静默。所有开页与财务动作仍通过项目正式脚本执行，不调用助手自带浏览器或电脑操控。

## 当前Native Messaging入口（2026-10-28）

Mac原生桥的公开`access(action="new-interface", silent=true, separate_window=true, execute=true)`已接通，创建固定学校入口的新独立窗口。也可省略`separate_window`在明确绑定的旧窗口新建后台标签；`tab_id`可省略，给定时核对并保留旧页。原生桥明确不请求窗口焦点，但不观察其他应用前台，所以`foreground_observation_supported=false`、`quiet_verified_at_observation_points=null`；不能声称已核实全程前台不变。显式`silent=true`经过统一参数归一化后仍保留，即使本案为`full_control`。

`wake-interface`只恢复指定原标签，不能继承`full_control`的新开页专属开关`--allow-foreground-open`，也不接收`silent`或`separate_window`。统一入口按动作限定参数，避免旧案在业务读取前因误带开页参数而失败；新开页及原开页恢复的既有模式保持。

每次先保存稳定开页意图，再调用一次原生建页。回执核对原生创建ID、namespace、窗口、旧活动标签和旧财务页。超时或身份不闭合时保留原意图；`recover-interface`只盘点原创建ID，不领用用户同期新开的页、不重复开页、不关闭旧页、不重放财务动作。同一请求号不能换模式。

新页用实际`new_tab_id`运行`access ensure`。认证复用当前会话，确实到CAS登录页才通过已配置的密码库引用和内存凭据通道提交；沿官方跳转和签发URL进入实际业务标签，不模拟点击、不复制Cookie、不保存SSO参数。随后用`access check-backend`核验本人账号与真实W70接口；缓存用户名、主页面可读或HTTP200均不能单独证明后端就绪。

`RegisteredSession.ensure`遇到真实后端401/403/404或无法确认响应时，对当前已登记页最多沿上述公开入口新开一次、认证并独立核验。开页、登录、核验分别留原job和恢复指针；失败保留新页及原登录意图，不循环开窗。有未知财务写入或要求`preserve_original`时不自动换页。已登记的CAS/首页标签也可按原归属续办，冻结时先恢复原文档。

2026-10-28实测：旧页缓存账号可读但接口404，新入口实际退到CAS，重新认证后同一YBX地址恢复。密码库曾因本机连接超时不可用，修复其既有网络连接后登录成功；不能把取凭据失败推断成学校后端故障。健康检查现与业务复用学校jQuery传输及解包，避免原始fetch返回包装被误报为合同变化。实际恢复范围与速度见[底层业务接口](底层业务接口.md)。

历史AppleEvent适配的`silent=true`仍返回`silent_open_unavailable`；其`silent=false`可能短暂置前并记录恢复，不能将这一历史限制套到Native Messaging。旧`ustc-finance-background-plan-v1`只保留恢复读取，不能派发旧命令。Windows原有开页合同不因Mac实测自动升级验收。

## 先判故障层，再恢复

Mac Native Messaging的`access(action="wake-interface", tab_id=原页, execute=true)`接入原文档恢复。未冻结时只盘点；活动页走固定唤醒；混合窗口中的后台冻结页绑定同次盘点的用户活动标签，把原tab移入独立后台窗口，校验原活动页未变。只改变窗口，不刷新、导航或执行原业务。注册工作流的阶段入口自动执行同一恢复逻辑；维护入口`bridge relocate-frozen`也自动选择独立窗或混合窗路径，不需要用户常规点标签。

回执先保存恢复意图，迁移后先落新窗口再独立盘点。同一请求重复接续只返回原回执；超时保留unknown，不重复迁移。有未知保存时恢复后仍读回原单，不能因页面唤醒就清pending。返回的window_id用于后续新读取；旧marker的跨窗口恢复仍须原登记迁移证据，不任意放宽epoch或后端绑定。桥升级可能改变epoch，已结束原保存可用同单独立回读核对，未结束原marker不能借升级重放。

状态分开处理：`document_discarded`说明原文档已被浏览器丢弃，不能当普通休眠刷新；`freeze_state_unknown`保留现场查桥能力；`recovery_unknown`查原桥回执及原tab位置；后端过期继续走下方认证恢复；桥失联走`bridge diagnose/recover`。这些状态均不自动关原业务页或新建报销单。新工作页优先显式`separate_window=true`，减少后台标签休眠和用户窗口混杂。

首次页面超时后，先用`access(action="check-page", tab_id=当前页, expected_userid=本案登录人, execute=false)`。该固定只读探针使用3秒桥接预算，不读取全表、不导航、不切标签、不重发业务。实际整项任务还含排队和进程启动时间，不能把3秒说成端到端耗时承诺。

| state | 已证明 | 下一步 |
|---|---|---|
| transport_unavailable | 当前桥接未能读回小型探针 | 保留原意图；先恢复连接，停止同一页反复大快照 |
| wrong_page / identity_mismatch | 页面或账号未匹配 | 首页、SSO入口或登录壳被业务页过滤拒绝时，补读原生标签地址，明确记为wrong_page；沿access及返回的实际业务tab_id接续，禁止填写 |
| main_readable | 缓存登录人、项目及主页面可读 | 再用check-backend核验真实接口；尚未证明会话有效、预览就绪 |
| preview_not_loaded / preview_unreadable / preview_not_ready | 主页面可读，但原生预览不可用 | 查预览和连接；HTTP200不能代替页面加载 |
| preview_identity_mismatch | 预览单号与主页面不一致 | 停止办理并核对，不能只按金额绑定 |
| preview_ready | 同单号预览正文和原生栏目入口均存在 | 独立核对本案票数/金额/GUID后续办；不等于已保存或已提交 |

探针通过MAIN world读取业务上下文；AppleScript隔离环境能看到DOM却看不到`$`时，不能误判未登录。临时探针节点同步清理，已有业务marker不动。

同类读取/加载故障重复出现时，禁止以换请求号、反复加长等待或追加包装工具冒充修复。先写出“观察到的现象、已排除项、尚未证实的原因”。恢复动作回执、HTTP响应正常、mock通过分别不能替代同一原单的现场验收。

重启会使旧标签ID和原生页面标记失效；先重新盘点，不把旧ID带入新实例。恢复标签与恢复登录分别核验，原服务器单据及本地未知意图保留。登录提交后遇到`wrong_origin`，使用`access(diagnose)`检查是否为地址栏仍指向学校的浏览器错误页；`null`文档来源及`ERR_TOO_MANY_REDIRECTS`是错误页证据，不是账号不符，也不是已证明Cookie根因。仅获准重置连接不能自动扩大为重启整个浏览器；整浏览器重启另有明确授权时记录范围和结果。内部设置被工具策略阻止时不绕过。

## 固定流程

1. 优先复用正式脚本盘点得到的现有财务标签，按上表分层读取。旧助手浏览器开页方案已停用，不能因连接故障换通道。
2. Native Messaging用`access(new-interface, execute=true, silent=true, separate_window=true)`保留旧页并创建独立入口；只有历史AppleEvent静默开页仍未支持。取得实际new_tab_id和独立原生盘点后才继续登录。
3. 历史`ustc-finance-background-plan-v1`只能通过`access(recover-interface, job_id=原计划任务, artifact_id=原计划回执, execute=false)`核验已发生的结果，不再派发其旧命令。它不新开页面，也不清除未知业务。
4. 用实际标签ID正式核对`WF_YBX`及登录人。登录壳使用现有`access ensure`流程；开页、登录和业务恢复分别留证。本人日常票池直接用固定HTTP `business(invoices-list)`完整读取53表，无须先打开票池界面；历史`view="pool"`参数仍只表示从识别明细返回票池。
5. 除明确允许的新开页外，系统前台保持不动；后台登录临时保持目标标签，结束恢复原标签。不调用助手自带电脑操控或浏览器工具维护标签。
6. 旧业务结果未知时，先查原票/GUID或原草稿。新页不解除`pending_write`，不重放建单/保存/提交。`invoice_verification(view="drafts")`只打开草稿列表；`finance_cli inspect-draft`按实际单号、申请人、金额、草稿状态唯一匹配，打开原单后另行回读发票数量/合计或GUID占用，再正式`bind-serial`。
7. 仅当原生预览框已有固定学校预览地址、内容仍为空且位置仍`about:blank`时，`finance_cli recover-preview`可重载该空白预览框。它不重开草稿、不重建单、不保存。已有内容或地址/身份不符即拒绝，结果不明只读回查。
8. `finance_cli diagnose-preview`只GET当前DOM已给出的固定学校预览地址，记录HTTP状态及文本，不执行返回脚本。响应正常不代表iframe已加载，也不能代替单内发票核对。
9. 接续记录保存实际标签、单号、最近完整回读及未知操作，保留旧未知结果页，不调用助手浏览器交接方法。

仅当当前页为同账号、同单号的空白原生预览且没有可编辑字段时，低层诊断适配器`finance_cli recover-main`可向固定主入口请求一次GET重新加载；它不保存、不建单、不提交。该动作不是自动降级，须在已留存独立诊断的恢复任务中调用一次，之后用`check-page`回读。请求返回但页面未变，仍记恢复失败，不再次调用或清除pending。该适配器目前未作为自动编排环节接入MCP，不称已完成一条龙恢复。

`inspect-draft`与`recover-preview`使用只读上下文（case_id、真实serial、amount、system_mode=daily、expected_userid），不为打开栏目伪造未确认的经费和教师信息。其他填写保存仍走正式配置校验。

`bind-serial`核对单号、所选GUID或同单票数金额后，同时归档同案`invoice:create-draft`的待回读意图；回读必须晚于建单。已有相同单号可恢复本地绑定收尾，其他单号、其他操作或旧回执拒绝。不得手工删pending；也不使用`ack-write(saved)`替代绑定。

## 验证与限制

建单按钮返回404且旧页仍显示登录信息时，不能据此重放。保留原请求，用正式`access new-interface → ensure`取得新登录页与业务标签，再只读完整草稿列表和完整票池。维护适配器`finance_draft_session_recovery.py`只在原创建源码/范围未变、新入口确实跳登录页、重新登录链路明确、所有草稿早于原请求日、全部原票身份金额匹配且未占用时，登记SHA绑定的恢复证明；存在当日草稿、未完整读取或票据已占用即拒绝。登记不清pending，须以冻结票池回执`ack-write(not_applied)`后沿`invoice resume-draft`接续；原创建及恢复证据始终保留，新请求仍须独立回读和绑定实际单号。

重复行程提示需要缩小范围时，维护适配器`finance_draft_cancel.py`只允许取消同案冻结选择对应的原生提示。超时只恢复原标记；取消后独立完整票池确认无单号、无弹框、原票未占用，才可登记`cancelled_before_creation`。新的申报范围另建明确案件，不能用取消动作隐含同意继续或推定改签关系。

原生窗口需要隔离时，公开`access new-interface`的`separate_window=true`创建独立窗口并保留旧标签；恢复须保持原请求及同一separate-window设置。Native Messaging不请求焦点；历史AppleEvent是否允许短暂置前仍由本次授权决定。

离线测试覆盖：一次计划、重复拒绝、跨案件/命令变化拒绝、唯一新增与多候选、焦点/原标签变化、草稿身份及金额不匹配。现场证据在各案件记录，不随源码发布。新页能读列表不代表预览、保存或提交已恢复；回执须保留具体失败阶段。

`new-interface`使用`ustc-finance-page-open-v2`回执，分别记录page_opened和quiet_verified_at_observation_points。历史助手浏览器计划仍为`legacy_browser_bridge_disabled`。已有页面的读取、姓名核对、填报与保存走项目脚本，能力缺口不能用其他操控渠道掩盖。

闭环验收必须用同一原单走完：后台开页→核对账号→找回原草稿→核对票据→进入实际填写栏目→保存并独立回读→到本人提交关口。中途不能要求用户常规切页，不能再次建单，不能只用模拟页面代替现场。现有功能测试只保证各入口约束，不证明这条完整链路已经通过。

原生AppleScript建标签实际使用前台标签模式，参考[Chromium原生实现](https://chromium.googlesource.com/chromium/src/+/19b52c097bfeb38304d4243fea5eff8aeb3140c9/chrome/browser/ui/cocoa/applescript/window_applescript.mm)。历史`ustc-finance-session-v1`仍可恢复旧回执；只有历史AppleEvent入口需明确silent=false。当前Native Messaging入口及其观察边界以上方说明为准。
