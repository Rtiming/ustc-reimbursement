# 材料核对工作台

本地可交互的事项、材料和问题工作台。复用既有归一化输入、材料组映射、最新问题台账及冻结Excel映射；新增索引与反馈事件留在案件工作区。不会调用财务接口或发送消息。

## 日常使用

从本案的打开入口启动，或在正式检出运行：

```sh
bash tools/reimbursement.sh material-review open --workspace /本案/材料核对工作台
```

`open`在本机启动或复用工作台并打开浏览器；只要进程仍在运行，浏览器关闭后可再次打开。`start`只返回本机URL。默认端口8766，可用`--port`指定未占用端口，`--port 0`自动选择空闲端口；不会接管其他程序。`serve`在当前终端运行，Ctrl+C停止。启动会检查Python、材料依赖和工作区可写性；同时点击打开通过操作系统锁串行处理，进程退出后锁自动释放。

`doctor`检查依赖与工作区；`status`返回是否运行及代码是否为当前版本；`stop`通过已认证的本机接口停止服务并读回，不按旧PID盲目杀进程。代码更新后必须先`stop`再`open`，避免页面新代码与后台旧实现混用。保存/停止通过同一服务写锁协调。浏览器关闭前有未保存文字或文件会提示；这个提示不等于草稿已经保存。

界面支持按序号、活动、社团、完整票号及材料名检索，并按办理队列筛选。从费用行、明白纸或问题跳到材料页，可放大、换页、下载原件、反查所属事项和复制当前位置。原金额口径与历史系统采集时间分别展示。

- 在“问题与反馈”下填写答复或拖入、多选补件，文件关联到当前事项及问题。
- 在“明白纸、清单与材料”下也能向事项直接补件，不必先制造问题。之后可在具体问题下将该补件关联为证据。
- 补件类别由用户选择；类别只是整理标记，新增材料始终待复核。单份不超过20MB，每次最多20份，可逐个移除已选文件。
- 未发送的文字和已选文件自动保存在当前浏览器的 IndexedDB，刷新后恢复；这份本机草稿尚未进入案件事件记录。保存成功后自动跳到下一条待处理问题。
- “清除本项未发送草稿”只清除本机未提交文字和文件；已经保存的事件与原件保留。原保存结果未知时禁止清除，重试沿原请求编号恢复。
- 多份补件逐份追加，失败明确报告已完成数量；未完成文件仍保留。未知保存结果重试同一请求，不重放为新记录。
- 记录人可留空，事件登记为“未署名”。复核须填写说明，逐项勾选完成条件并选取证据。登记复核不会改变学校系统状态；可追加重新核查记录。
- 反馈包默认只导出待处理问题，可在顶部按社团和问题勾选，解压后打开`index.html`。只含所选、可直接对外反馈的问题及明确对应的证据；跨范围共享材料不自动外发。生成与发送分开，系统不发送消息。

Excel仍走原冻结校验入口，导入仅登记待复核答复：

```sh
bash tools/reimbursement.sh material-review import-answers --workspace /本案/材料核对工作台 --workbook /已填写文件.xlsx --actor 记录人
```

读取工作台配置中冻结的确认映射，验证全工作簿及问题集合后按问题追加。相同文件的相同问题不会重复导入；部分导入中断可以接续。Excel中的“已补”“确认”或复核文字不会自动变成网页中的已复核。网页事件不反向改写已发出的冻结Excel。

## 衔接正式做单

“办理去向与做单准备”使用带时间的完整系统回执，将事项分为待投递、待本人确认、已建草稿、仅做草稿准备、新建准备及暂缓。已登记单号优先匹配原单，不因材料问题为空而新建另一张。已有草稿不会因材料问题而被标作不能继续做单。明确仅做草稿的授权从归一化输入的 `material_review.draft_authorized` 和 `draft_authority={path,sha256}` 读取，构建时核验来源；不会从一条自由文本答复自动推断。问题及提交前核验仍保留。材料问题全部复核仅表示可检查做单条件；金额、经费、收款、票据占用及审批条件仍归正式工具检查。

维护人先由正式 `business(action="bills-list")` 原生 HTTP 接口读取完整清单，并取得正式 `cases` 输出，再导入：

```sh
bash tools/reimbursement.sh material-review import-workflow --workspace /本案/材料核对工作台 --config /本机/办理连接.json
```

配置包含 `tool_root`（本机正式工具检出）、`batch_case_id`、`expected_userid`、`source_job_id`，以及 `source`（完整只读任务回执）、`cases_source`（案件列表）的 `{path, sha256}`。只接受原生接口完整成功回执，校验账号、案件、原单及已核申请金额；部分结果或漂移不能替换旧快照。仅保留本材料批次登记的单据，不复制同账号其他案件。更换材料数据版本会使原办理绑定失效，须重新核对。

页面“进入正式做单预检”只执行固定的正式 `overview(case_id)` 本地检查，保存参数错误、未确认写入、在途任务及原单关联回执。接口不接受任意命令、路径或 `execute` 参数，没有财务执行路由；不能将预检回执当作新建、保存、提交或本人确认成功。未登记正式案件的事项先补材料、核定参数并由正式程序生成计划，本页不会猜测创建案件。

工作台的 `workflow/versions` 保存范围内状态版本，`workflow/preflights` 保存本地预检依据；本机程序连接存在代码仓 `.local/review-runtime`，不随材料或接续包导出。精简接续包可继续核对补件，重新办理须在接手设备配置正式工具并核对状态。经办仍沿正式工具接续，学校提交、本人确认和短信各自保留原有办理条件。

## 输入与重建

配置由案件维护；所有来源须显式给路径和SHA。首次构建和更新：

```sh
bash tools/reimbursement.sh material-review build --config /本案/材料核对工作台/config.json --workspace /本案/材料核对工作台
bash tools/reimbursement.sh material-review verify --workspace /本案/材料核对工作台
```

配置格式：

```json
{
  "schema": "ustc-material-review-config-v1",
  "title": "材料核对工作台",
  "batch_id": "明确批次标识",
  "roots": ["/本案资料根"],
  "batch_root": "/本案资料根/收件批次/本批",
  "sources": {
    "issues": {"path": "/最新问题台账.json", "sha256": "实际SHA"},
    "normalized": {"path": "/已核归一化输入.json", "sha256": "实际SHA"},
    "mapping": {"path": "/材料对应总表.json", "sha256": "实际SHA"},
    "annotations": {"path": "/材料标注.json", "sha256": "实际SHA"},
    "confirmation_manifest": {"path": "/冻结填写映射.json", "sha256": "实际SHA"}
  },
  "expected_counts": {"items": 1, "issues": 1}
}
```

`issues`消费既有问题整理快照中的`materials/issues/resolved_prior/formal_pdf_mapping`；`normalized`消费原批次`documents`和费用/票据关系；`mapping`消费已盘点的`groups/files/photos`。`annotations`和`confirmation_manifest`可省略。未登记来源、SHA漂移、页码越界、跨事项证据和越根路径会拒绝。旧Windows路径只按明确的SHA工作副本/MI照片目录映射，并重新核SHA，不按同名文件猜测。

新来源先另存并核实，再明确更新配置路径/SHA后重建。相同输入得到相同快照，旧版本保留。事项和费用沿用既有ID，材料按SHA标识，问题沿用原编号；反馈绑定问题定义指纹。新定义不会继承旧的复核完成状态，但保留原答复、补件和记录，并提示需复核旧结论。

精确圈注及已核更正独立放在`annotations`：`issues[问题ID].targets`指定材料SHA、页码、标签及可选归一化矩形`box=[x,y,w,h]`，有框必须填写核实`basis`；`requirements`列独立必要条件。`expenses`补有依据的费用纠正；`assets`仅允许材料类别和预览旋转。不能用标注覆盖源文件路径或SHA。原纸只有总额时，仅关联到事项，不伪造明白纸行号。

## 整理、导出与经办交接

页面顶部“整理与导出”提供四种用途，默认格式为可直接打开的PDF文件。默认只勾选可对外反馈、状态为待处理的问题；已答复、已安排补件、提交前待办及暂缓项默认不选。可按社团、事项范围、进度筛选，再逐条勾选或取消；切换筛选会按新范围重置勾选。预览显示问题数、事项数、材料数及省略数量，零选择不能下载。所有导出仅生成本地文件，不发送、不上传。CLI通过`export --mode`调用同一实现。

选择以问题编号为单位，而不只是事项编号：同一事项中未勾选的问题也不会写入问题清单。材料浏览包仍附所选事项的已有分类材料用于对照；轻量反馈包只附勾选问题对应的材料页。筛选后有新回复或材料更新时拒绝旧选择，须刷新再导出。已答复问题仅在用户切换进度并显式勾选时导出，保留进度提示，不泄露内部回复原文。

|用途|范围与内容|接收人如何使用|
|---|---|---|
|`pdf`直接查看文件（界面默认）|按具体项目展示范围、明白纸对应、费用清单、材料整体圈注；同页紧凑排布，不追加独占整页的发票；未明确关联的跨范围材料、正式打印件和无法显示的格式省略并登记|单个PDF直接打开，无需解压、安装或原工作台；书签跳到项目，中文字体嵌入，材料整体固定显示|
|`feedback`问题反馈草稿（默认，兼容原接口）|默认只含所选事项待处理的可对外问题；可显式指定问题编号；明确证据，PDF只截对应页；省略范围外共享材料|解压打开`index.html`，按问题编号答复|
|`materials`材料浏览包|明确所选事项的分类原件、明白纸/费用/问题关系、逐页预览、局部对照；无内部经办备注、收款安排或系统办理记录；范围外共享材料及正式财务打印件列入未包含清单|解压双击`index.html`，无需安装、联网或原工作台；保留搜索、跳转、翻页、放大和下载。只读快照；补件交经办人登记|
|`handoff`经办接续包|完整案件当前索引、全部原件、补件、原字节事件链及引用的历史快照；只带材料工作台所需代码、固定依赖、启动入口与说明，不带会话访问码、浏览器登录、虚拟环境或财务执行器|配置Python3.10以上及锁定的PyMuPDF/Pillow后启动；继续补件、回复、复核和导出。供指定经办人使用|

```sh
bash tools/reimbursement.sh material-review export --workspace /本案/材料核对工作台 --mode materials --item 7
bash tools/reimbursement.sh material-review export --workspace /本案/材料核对工作台 --mode pdf --item 7 --issue 问题编号
bash tools/reimbursement.sh material-review export --workspace /本案/材料核对工作台 --mode materials --item 7 --issue 问题编号
bash tools/reimbursement.sh material-review export --workspace /本案/材料核对工作台 --mode handoff
```

`materials`必须明确`--item`，可重复提供。`--issue`可重复，严格校验属于所选事项、可外发且未复核；显式空选择拒绝。省略`--issue`时仅附待处理问题。`handoff`不接受局部事项或问题选择，否则无法完整保持事件链；界面明确显示完整案件范围。已有反馈包接口仍默认`feedback`。轻量反馈包附可填写的`问题反馈.csv`，补充文件按问题编号交经办登记；此表不冒充原冻结Excel导入映射。

浏览包和接续包采用`ustc-material-review-package-v1`：根目录`manifest.json`固定来源版本、事件版本、事项范围、每个成员的大小/SHA及未包含原因。`清单/`含事项、材料（含新增补件）、问题CSV，接续包另含处理记录CSV（UTF-8 BOM，公式起始字符转义），原件保持字节和类别；预览图片、裁切页与原件身份分开标记。`校验包.py`无需第三方依赖，验证初始交付成员。CSV是便于检索的附表，原冻结Excel清单继续作为原有交付件，不被覆盖。浏览包不含打印排版，正式单面附件仍由原打印工具生成。

导出先写临时包，源文件逐个核SHA；只有当前索引及事件版本保持一致才原子发布。失败不留下可误用的半包。文件名使用归档内容SHA，不覆盖不同历史包。`manifest`是完整性校验，不是第三方签名或真实性认证。

接续包当前索引使用`storage=portable`及`originals/`下相对路径；历史快照和事件保持原字节供追溯，旧的绝对路径只作历史来源，不参与当前原件读取。完整源码仓保留重建、冻结Excel读回及正式办理连接能力；精简接续包不携带这些源输入与本机连接，明确拒绝这三项动作。

交接采用单一写入副本：先保存、导出，再停止旧工作台；接手人验证并在接续包继续写。交还时从新副本再次导出，不能将两边的事件目录直接合并。此版本没有多经办同时写不同副本后的自动合并功能。修改原件或日志后校验失败，应按原始备份核对恢复，不能跳过损坏记录。

导出范围依据已登记事项归属；无法据此保证原件内部没有第三人的信息。系统不会自动把含多事项的共享文件拆成不同人的原件；省略项在manifest记录，发送前由经办查看实际包内容。

## 保存位置与恢复

|位置|性质|
|---|---|
|`config.json`及材料标注|本案维护的输入指针和核实后的定位/更正|
|`versions/<SHA>.json`、`current.json`|可重建的冻结材料索引及当前指针|
|`events/00000001.json`等|不可覆盖的反馈事件，含前条SHA、来源版本、记录人和时间|
|`attachments/<SHA>.<扩展名>`|新增原文件，按内容去重；不覆盖旧原件|
|`exports/`|版本固定的反馈草稿、材料浏览包及经办接续包；不代表已发送|
|`workflow/`|范围内正式状态快照及本地做单预检回执；不会写入财务系统，也不随材料分发包导出|
|工具检出`.local/review-runtime/`|仅本机的进程、日志与短期访问码，不同步、不入Git|

没有共享活跃数据库。事件先完成临时文件写入，再以排他方式发布；并发版本冲突返回错误，不覆盖另一位经办的记录。事件缺号、链或字节损坏会停止读取，须从备份核对恢复，不能删事件跳过。原件SHA变化会拒绝预览/导出，不能改索引SHA绕过漂移。

原资料模式迁移时，按既有案件资料同步保留配置、版本、事件、补件和原件，新设备明确设置本机来源路径后构建新索引；也可以使用完整经办接续包直接在新目录使用。不要同步`.local`和临时访问码。当前已验Mac本机运行；多设备同时写同一案件、Windows启动和断电文件系统恢复尚未现场验收。

## 实现和检查

`assistant.py material-review`为统一CLI入口；`material_review_build.py`导入；`material_review_model.py`校验；`material_review_store.py`追加记录；`material_review_server.py`只在127.0.0.1服务登记材料；`material_review_export.py`维护兼容反馈包；`material_review_package.py`管理材料/接续分发契约；`material_review_launch.py`管理启动、检查与停止；`material_review_distribution/`保存精简启动入口、接手说明和完整性检查器。分发入口调用相同CLI实现，不复制业务逻辑。界面在`tools/material_review_ui/`，在线与离线使用同一呈现逻辑，无外部脚本或CDN依赖。

基本运行使用Python标准库；PDF/图像预览使用材料环境已有PyMuPDF/Pillow。不会启动OCR。读取原件须在登记根内且SHA匹配。大原件与接续包按块传输，健康检查不重复读取全部材料索引。页面以临时访问码建立HttpOnly/SameSite会话，写请求另校验本机Origin；没有任意文件读写、目录浏览或财务转发接口。

直接测试为`python3 -m unittest discover -s tests -p 'test_material_review*.py'`；基础测试覆盖来源绑定、重复请求、旧版本/并发拒绝、复核条件、补件/事项入口、跨事项/页码、事件篡改、对外范围和HTTP边界；交付测试另外验证原来源消失后接续、独立代码再导出、启动/停止/重启、并发启动、代码更新拒绝复用、路径与篡改拒绝、原件/清单和逐页预览。完整项目检查仍用`tools/check_project.py --suite all`。浏览器验收单独使用隔离副本和file://浏览包，不向真实案写测试反馈。

## 本模块维护范围

稳定化以本材料工作台为边界，不改变全仓财务业务层。导入/定位继续复用既有冻结输入与SHA；模型/记录继续使用不可变原件和追加事件；运行层新增检查、升级检测和停止；导出层补齐独立浏览/完整交接；界面共用呈现、明确只读/可编辑模式并保留草稿提醒；验证和文档覆盖实际接手链。PDF打印排版、财务提交、多人服务部署和双副本合并分别保留在已有owner或明确未实现边界，不以本机测试宣称这些能力通过。

## 反馈入口与待办状态（2026-10-30）

本轮范围是入口发现、回复处理、材料待办与正式程序接续；不改变财务提交权限。正式源码持有实现，案件目录持有原件、快照和事件，本机`.local/review-workspaces`仅登记入口。已有工作台不重建、不复制材料库；切换代码所有者前从旧入口正常停止，再由正式入口启动并读回原事件链。

统一入口：`capabilities(intent="review") → material_review(action="list")`。首次登记使用`material_review(action="register", workspace="工作台绝对路径")`，之后`open/start/status/doctor/stop/summary`均用同一workspace。JSON方法为`material_review`，MCP名为`reimbursement_material_review`。workspace必须位于显式配置的material-root，list只列当前可访问的登记项。`assistant.py material-review`继续作为参数入口；构建、导入冻结答复和导出仍复用现有实现。

首页反馈总览按当前事件重放统计：待回复、收到答复/补件待复核、答复已处理但等待材料、提交前补齐、明确暂缓、材料已复核。后续待办用`defer`事件登记，必须给stage（waiting_materials/before_submit/hold）和具体说明；它不关闭问题，也不自动授权做单或提交。新答复、新补件或问题定义变化会重新进入核查。材料状态与财务草稿、申请人环节、投递状态分开；“已回复”不能代替“已复核”，“已有草稿”也不能代替“系统检查通过”。

默认保留保存回复后自动跳至下一条待回复；可关闭开关连续补件。开关、未发送文字和文件持久保存于本浏览器。清除仅影响未发送草稿，已保存事件不可删除。点击总览问题跳转原件页；原单只经正式工具本地预检，命令使用当前Python，避免依赖bash而使Windows失效。

验收覆盖：范围限制和入口登记、事件留痕和新补件重新待核、原单复用与无财务写入、页面跳转和草稿持久、材料/反馈/经办包再导出；公共发行源清单需包含运行模块、UI、测试和本文，纯净包实际启动验收后才称可交付。

启动URL包含不携带材料的本次启动标记，重启后重新进入会加载新会话。不同端口的工作台使用各自HttpOnly会话cookie，避免同时打开两个案件时互相覆盖。旧运行记录仍可由原入口正常停止。

页面收尾：右上角“结束使用”先等待浏览器草稿落盘，再释放页面连接并尝试关闭本标签；正在保存或草稿存储失败时保留页面。浏览器禁止脚本关闭的标签显示已结束页面，交给浏览器关闭，不能宣称已关闭。页面连接只在运行内存中保留75秒，20秒续期，不写案件事件；失联页面自然过期。`open`检测到有效页面连接时返回复用提示，不再反复创建新标签；关闭最后一页后仍可从原入口重开。

助手收尾约定：先盘点本任务的工作台标签，复用可用页；仅关闭已确认无未保存内容的重复/旧验收页，保留一个当前交付入口。失联页通过浏览器提供的关闭接口处理；接口不可用时明确记录未关闭，不绕过桌面应用权限、不终止整个浏览器或财务会话。

新设备可使用正式发行包的一键安装器，以`--data-dir`明确材料范围，`--review-workspace`登记已有工作台；安装后报告提供直接打开入口，只有一个有效登记时省略workspace可直接open。多个登记时须明确选择，不自动扫描资料目录或复制案件。精简经办接续包本身仍使用包内Python启动说明；希望自动安装运行时及MCP的使用者应配合完整工具发行包。详见[部署指南](部署指南.md#一次安装并接续反馈台)。


### 明白纸关系与补充者视角

收到某张明白纸、文件归属某事项、与票据属于同一费用范围是三件事。`annotations.items[事项ID].paper_relations`显式登记关联：每条包括`asset_id`、`page`、`source_item_id`、`relation`、`statement`和`basis`。类型为`same_scope`（同一费用范围）、`different_scope`（同活动不同费用，不能替代）、`unverified`（费用范围待核）、`paper_only`（已有原纸但缺费用或领取明细）。旧数据只有`paper_ids`时显示已收、范围待核，不自动宣称匹配。

同活动不同费用或候选明白纸仍应展示整体，并说明纸面事实、票据事实及仍待核的关系。跨事项背景仅接受明确登记、来源事项和SHA已校验的明白纸；不得添加其他原件或财务打印件。PDF和材料浏览包附该张纸并保留来源编号，不导出来源事项的其他材料和内部记录，不把关联当作费用归属或合并金额。导出预览说明会带入这些关联纸；已答复项目仍默认排除，显式选出时保留后续安排，不重新催答。

已核定的`issues[].feedback`补充说明由正式`summary`和网页共用：待回复事项采用当前说明，已有后续安排仍优先。离线材料包的页面、问题CSV和局部放大同步使用该说明及其证据位置；仅传对外字段，不携带内部答复、后续安排原文或其他事项材料。兼容反馈草稿的文字要求同样取当前说明。

PDF排版只读取原件尺寸与EXIF方向，在一次导出内按材料ID和页码复用尺寸；实际输出继续核验原件SHA并按216dpi渲染。没有跨请求的原件或事件缓存，修改材料或新答复仍触发原有校验。测量需从正式CLI开始到文件落盘，按同版本材料、同选择和同分辨率交错比较；对照全部页面文字、图像、书签、链接及材料清单，不以仅测渲染函数或降低画质声明整体提速。

费用的可选`review_note`保存已核已知信息，`candidate_amount`仅为文件名候选金额，`reply_needed`说明是否需要补充者答复；均不改变申请额、付款、实际收款或问题指纹。先填好已有日期、人员、路线与材料，再只问仍缺的信息。多笔同类差异允许统一确认或仅更正例外，主动少报不自动变成索要付款差额证明。两份纸票材料能容纳时同页比较；只展示有用途的材料。

验收由补充者回答：是哪项活动和哪一组费用？已有哪些纸票，哪些只是相关背景？具体哪一处不一致？仅需补什么，怎样合并回复？必须用“同活动劳务纸不能替代有票费用”和“纸票金额不同、既有草稿不重建”两类合成例检验关系与状态不混淆。

### 问题材料与局部特写

问题核对页按原件页合并圈注，同一原页只显示一次；点击按钮才放大圈注区域，其他材料与下载入口默认收起；无框选时显示对应明白纸或已有票据，明确为对照材料，不把缺失材料伪造成图片。离线浏览包同时携带原页、框选预览和特写。

PDF按“项目与金额范围 → 明白纸对应 → 需处理及回复内容 → 费用对应清单 → 整体图＋编号圈注”排布。已有明白纸必须显示本项概览；未定位到的明确写出，跨范围省略与未收到分开。编号M表示本项明白纸、F表示原件顺序，费用关联仅从已登记的费用—原件关系读取；完整票号、文件名、票面金额用于指认，文件名中的实付候选不能自动当核定额。清单对已展示材料提供文件内跳转。每张关联材料只显示一份整体图，直接圈出位置，旁边按圈注编号说明；整体已经展示的，不再附重复特写，也不让一张发票独占整页。多处圈注留在同一原页，续页重复项目及需处理事项。

使用者不需要先读原材料包：先确定项目、已有哪些材料和缺什么，再按材料编号说明或补件。问题短文应写出可直接回复的字段，不增加已撤回的审批要求或重新索取已确认资料。普通PDF不依赖本机路径或工作台服务即可看全以上内容。manifest分别保存overviews、annotations、费用对照、明白纸状态与源SHA；查看副本与原件身份分开。

案件维护人可在`annotations.issues[问题ID].feedback`登记已核对的对外短文，包含`project`（具体项目，最多120字）、`request`（需补内容，最多600字）、`context`（必要已知事实，最多400字）及`issue_fingerprint`；可选`response`（具体回复字段/补件形式，最多600字），可选`evidence`明确本次对外展示的原件裁切区域（资产ID、页码、box、basis、label）；不选的旧圈注保留在历史，不继续外发。必须绑定当前业务问题指纹；业务定义变化时拒绝沿用。短文不参与业务指纹，不改变已有答复、复核及延期状态；不提供短文时沿用事项名和原问题请求。原问题定义与处理记录保留。

PDF使用独立的纸面渲染路径：按最终显示尺寸直接从原PDF页面高清渲染，不复用网页缩略图。照片保持原始像素上限，不通过放大制造清晰度。材料整体固定为216dpi图像，让文字与底图一起显示，避免接收者阅读器因字体或CMap兼容问题丢掉文字；源文件及SHA不变。材料图像不提供原PDF文字选择，项目说明可选择；manifest的`layout=project-relations-v4`及材料的`rendering=overview_fixed_appearance_216dpi`；圈注记录为`outline_on_overview`，兼容字段`closeups`为空标明实际方式。

渲染改动须用独立阅读器验证：除生成库外，至少检查Poppler渲染；Mac可再用PDFKit。重点核对整体圈注、照片方向、中文字体、长说明换行、同页项目边界及书签跳转，不能只凭生成成功或文字提取判定视觉通过。

已有问题可经追加`link`记录补充展示位置：`target`仍使用原件SHA、页码，可带`box=[x,y,w,h]`和必填`basis`。坐标在EXIF纠正后、预览旋转前的原页上归一化；裁切、红框及整页沿同一旋转显示。多处框选分别保存，即使同一原页也不合并丢弃。越界、非有限数值、无依据、跨事项或源SHA变化均拒绝。添加展示位置不改变已答复、待材料或复核状态，不重写既有问题定义。所有展示图为副本，原件不绘框、不修改。
