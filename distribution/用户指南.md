# 新用户使用指南

这份工具适合经办人让自己的AI代理整理报销资料、维护有来源的规范、生成离线计划，以及在配置完成后操作学校财务系统。初次使用先完成一次不登录财务的演练。

## 1. 先选使用范围

| 使用范围 | 可以从哪里开始 | 需要另外准备 |
|---|---|---|
| 收件、规则、离线规划 | 包内Python工具和JSON接口 | 原件、资料目录、本单位有效规则 |
| PDF材料整理 | 安装材料依赖后调用原工具 | 明确的纸电材料归属与打印计划 |
| 扫描件OCR | 正式收件后使用material_ocr | 已配置远程提供方，或显式--with-ocr启用本地CPU模型 |
| AI直接调用 | stdio MCP或CLI/JSON | 支持本地工具的AI客户端及其本机配置 |
| 科大财务网页办理 | 正式浏览器适配器 | 本人账号、学校网络、本机Edge接线和逐动作验收 |
| 总账、手机采集、Excel成品 | 视本机能力选择 | 外部运行服务或表格创作依赖，本包不附带 |

Mac已有原生桥实现；Windows已有桥和安装工具，但新用户设备仍需自己的接线和实机验收。0.4正式发行的登记整批仅支持Mac；0.5候选已加入Windows接口，但用户暂缓现场验收，不能把接口合同测试当作真实业务已通过。Linux主要用于离线处理，不支持本包的财务浏览器操作。短信验证码始终由本人填写。

## 2. 解压并划分目录

将工具解压到自己可写的新目录。另建一个专用于报销资料的目录，不要授权整个用户主目录。工具、私人规范库、具体案件和本机运行状态是四种不同内容：

```text
工具目录/                       本包源码与说明
  cases/                        使用后产生的本机案件登记
  .local/                       使用后产生的任务、回执和设备配置
资料目录/
  规范库/                       本单位共用和项目专项规则
  项目甲/批次01/                原件、确认记录和交付文件
  项目乙/批次01/                与项目甲分开
```

`cases/`、`.local/`和真实资料均不在分发包里。复制工具给别人时重新运行打包工具，不直接压缩自己使用过的整个目录。

## 3. 安装和第一次演练

推荐从一键入口开始。在解压后的工具目录运行：

```sh
sh install.sh
```

Mac也可以打开根目录“安装与自检.command”；Windows运行`install.cmd`。启动器校验冻结的uv原包，在当前工具的`.local/python`取得Python3.12.13，再建立`.local/mcp-venv`安装锁定依赖。它不使用作者的Python、uv缓存、私人技能目录或凭据，不修改全局Python、PATH和Windows注册表。首次需联网，Mac/Linux需要curl、unzip和SHA校验命令；Windows需系统PowerShell。系统阻止脚本运行时保留其提示，按组织允许的运行方式处理，安装器不绕过设备安全策略。

默认资料目录是本工具下`materials`，默认创建空专项`my_project`；这些是空白模板，不包含已确认的报销规则。需要指定目录和专项时：

```sh
sh install.sh --data-dir /绝对路径/报销资料 --profile-id project_alpha --title "项目甲" --mode student_activity
```

Windows把`sh install.sh`换为`install.cmd`，路径使用自己设备上的绝对路径。重跑安装保留已有资料和规则；已绑定的数据目录不会被悄悄切换。若原规范库丢失，会要求恢复原资料，不重置为空模板。

安装会生成`.local/installation.json`、`.local/client-configs/mcp.json`及`.local/self-check-current.json`。最后一份指向可打开的HTML报告，分开显示必需检查和可选外部服务；“基础功能已就绪”不等于本单位规则已核定或财务已接通。今后只自检：

```sh
sh install.sh --check
```

自检不联网安装、不修改规则；它使用临时合成资料运行CLI、真实stdio MCP和原件归档。Windows对应`install.cmd --check`。安装失败先看当前报告目录的install.log；网络恢复后重跑同一入口，不必复制别人的环境。

以下是已有Python3.11以上用户的手动入口，可用于诊断。已经通过一键入口安装后无需重复这些步骤：

```sh
python assistant.py --help
python tools/distribution_smoke.py --output /绝对路径/演练回执.json
```

Windows的绝对路径可写成`D:/报销资料/演练回执.json`；Mac/Linux替换成自己的真实路径。演练在临时目录使用合成资料，检查包内文件、命令入口、新案无旧身份和规则组合，不连接财务系统。成功应返回`ok:true`、`browser_actions_executed:false`。

需要MCP或PDF处理时安装本项目锁定依赖，仍使用自己的明确资料根：

```sh
python assistant.py setup --with-materials --material-root /绝对路径/报销资料
```

这会创建项目自己的`.local/mcp-venv`，不会改写AI客户端的全局配置。网络安装依赖与离线演练是不同步骤；Python安装方式由当前设备管理。仅接MCP可省略`--with-materials`。本包不携带Python、Node、OCR模型或外部依赖二进制。

依赖就绪后，用项目环境运行MCP演练：

```sh
.local/mcp-venv/bin/python tools/distribution_smoke.py --mcp --materials --output /绝对路径/MCP与收件演练回执.json
```

Windows把解释器替换成`.local/mcp-venv/Scripts/python.exe`。这项验证使用真实stdio MCP客户端，并将一份合成文本通过正式收件任务归档、逐字节回读；它证明相应协议和工具调用可运行，不代表每个AI产品的安装界面都已测试。

包内固定收录了共享archive_file归档工具的未修改快照，版本SHA登记在distribution/dependencies.json。setup将统一归档适配器接到本机运行配置；适配器核对冻结核心SHA，Windows读取复用原生句柄校验，不覆盖已有的不同配置；收件不再依赖发送者的技能安装目录。共享归档程序要求Python3.11以上，因此本试用包采用这一最低版本。

## 4. 给其他AI代理使用

MCP配置生成在`.local/client-configs/mcp.json`。将其中的服务配置导入或合并到自己的客户端，不覆盖原有其他服务。配置中的解释器、工具目录和资料根必须是接收者的本机路径；不要复制发送者的`.local`。

支持本地技能的客户端可加载包内`skills/ustc-reimbursement`。不支持技能也可以让代理读取`AGENTS.md`。只有命令工具的代理可以使用统一JSON入口：

```json
{"method":"capabilities","params":{"intent":"materials"}}
```

保存成请求文件后执行：

```sh
python assistant.py call --input /绝对路径/请求.json --material-root /绝对路径/报销资料
```

同一个操作，MCP名称是`reimbursement_capabilities`，JSON方法名是`capabilities`。不要从名称猜参数，详细schema在`mcp/tool_catalog.json`。耗时任务返回job_id，随后查result；普通退出成功不等于报销完成。

目录中的json_routes明确给出每个MCP工具对应的JSON方法；财务任务会注明method=enqueue及operation，不用猜测同名直调接口。CLI、MCP和安装自检共用本机安装绑定，安装后不会各自默认到不同资料目录。安装记录存在但依赖漏装时，自检会报缺项；重跑正常安装按锁定版本修复，不修改已有规范和案件。

materials/rules/ocr能力发现完全离线，不读取用户主目录中的浏览器桥注册或运行现场；finance/export才按所选功能检查本机接线。未探测的浏览器能力显示not_probed，不能解释为已接通或已失效。

可以直接告诉AI：“读取这个工具包的AGENTS.md。先做材料和规则预检，按我指定的资料目录工作，列出缺项；本次不办理财务写入。”之后再针对明确案件授权具体办理阶段。

## 5. 新建私人规范库和专项

从全新目录开始，先预览：

```json
{
  "method":"standards_init",
  "params":{
    "library_root":"/绝对路径/报销资料/规范库",
    "profile_id":"project_alpha",
    "title":"项目甲报销规范",
    "mode":"student_activity",
    "execute":false
  }
}
```

核对输出后将execute改成true执行。这只建立本地目录，不操作财务。已有目录会被拒绝覆盖。它生成共用`common`和专项`project_alpha`，专项通过`extends`引用共用模式；二者最初都是空规则、收集中。

调用`standards_read`列出或读取模式，再用`standards_change`预览新增/修订规则，实际保存时提供刚回读的`expected_sha256`。规则至少要有类型、状态、范围、作用、来源和确认记录。用`standards_select`按当前案件、业务日期和选择依据取得有效规则；未知、过期和冲突分别列出。

具体层次与继承边界见[模式与场景](模式与场景.md)。新专项只写差异；不同项目的个人信息和授权仍留各案。已有库追加专项使用`standards_add_profile`，不手改registry：

```json
{"method":"standards_add_profile","params":{"library_root":"/本机资料根/规范库","profile_id":"project_beta","title":"项目乙","parent_ids":["common"],"execute":false}}
```

预览返回`before_registry_sha256`。实际保存使用相同参数，加`execute:true`及`expected_registry_sha256`等于刚回读的值；之后用standards_read回读新专项。旧SHA、重复ID、未登记父模式和已有路径都拒绝覆盖。追加空专项不会确认其中任何规则。

## 6. 从材料到单据

1. 原包先归档，保留原件和SHA。`material_intake`负责收件；文字、图片、原纸来源分开登记。
2. AI核对原件，将材料整理成归一化输入。来源不明的金额、姓名、经费和日期保留未知。
3. 使用`prepare_batch_file`，给规范库、专项、当前案件范围、业务日期及输入文件。工具从所选规则生成policy，不让AI另抄一份政策。
4. 分别看结构、金额、导出及财务就绪度。规则未确认、必需规则未实现或实际材料有矛盾时，保留具体问题。
5. 清单分开列人员/拟打款、材料及费用、纸质原件安排；申请金额不得称作已付款。模板与原件投递要求按本单位确认。

第一次收件先建立一个本机案件，例如`{"method":"new_case","params":{"case_id":"my_first_batch","profile":"student_activity"}}`；这不建立财务单。再按`guide(topic="intake")`给出完整material_intake请求。MCP调用前缀为reimbursement_，命令调用可用`tools/reimbursement.sh call --input 请求文件`（Windows为reimbursement.cmd）；一键安装后会自动读取本机已绑定资料根。

试用包的合同、打印委托与预算默认值为未知。旧开发者的“通常无合同”等偏好不会成为新用户事实。`data/material_rules.json`初始未配置，材料检查会明确拒绝将其当作齐全；应按本单位制度维护该运行配置。私人规范库负责规划规则，两者尚未自动互相覆盖。

## 7. 财务操作前单独接线

新登记批次及Windows接线从[整批流程与登记](../docs/整批流程与登记.md)进入，统一使用bridge、register_workflow、workflow；无需手写内部索引、指纹或旧current_30指针。新版Windows能力处于候选验收阶段，不能以离线测试替代本案真实办理。

扫描材料先走[OCR统一流程](../docs/OCR统一流程.md)：ocr_status检查提供方，material_ocr从本案收件job选择缺文字页，执行后直接生成文字证据、回接清单和票面候选。默认不启用本地模型；没有服务器时可明确运行`sh install.sh --with-ocr`（Windows为install.cmd），安装器会用合成页实测。识别结果仍是候选，不自动填入财务字段。

先由本人在当前设备登录学校系统。自动凭据读取依赖单独的凭据适配器，普通用户可以保持本人登录；不要把密码或验证码写入JSON、发到聊天或打包给别人。

Mac可先执行`python assistant.py bridge status`，按报告准备、安装本用户的Native Messaging桥；`bridge prepare/install`只负责接线。Windows入口为`python tools/windows_bridge_setup.py status`，按其帮助和报告完成prepare/install。初次安装涉及浏览器扩展加载和本机权限，由本人确认；本包不会自动连接别人的浏览器。

通过接线检查以后，先`cases → overview → tabs/access`核当前账号和同案单号。检查、保存、本人批准和独立回读分别验收。学校网站结构变化应维护固定适配器，不能用通用点击、隐藏按钮或直接HTTP调用绕过。

已经登记的批次可使用workflow的fill、ready、approve、export-system、export-list、finish阶段。默认预览；ready只准备到本人待审，approve需要本案最终同意安排。finish先核全链输入，再依次批准、查看明细PDF、原生列表导出。其他单位的网站不在此能力范围内。

## 8. 输出、失败和升级

- 查看明细得到单据明细PDF，列表导出得到列表文件，正式预约打印受学校审批状态限制，三者不能混称。
- 已建立单据与文件映射后，保留原字节并重命名归档。缺文件、下载未结束或重名冲突保留原任务；不为归档重复审核PDF内容。
- 超时先查原job和pending。写结果未知不换请求号重发；原页面丢失不拿新页冒充。短信校验完成后沿原命令接续。
- 已完成文件可按原回执复用。历史复用速度不能作为新批准批次的测速；本包没有“整批5分钟保证”。
- 升级使用新的工具目录，先验收再接续；案件和规范保留原版本，不覆盖活任务，不复制账号会话数据库。运行记录与代码版本分别留存。

## 9. 尚需配置的外部能力

OCR已支持配置远程提供方或显式本地模型，二者复用同一内核及结果格式；普通安装不下载模型。批量总账仍使用现有远程计算适配协议，服务端不在包内；手机采集依赖已配置的设备通道。Excel成品导出依赖既有Node表格创作运行时，包内提供清单数据准备能力，但不捆绑该专有运行时。官方审批表应从本单位取得当前有效母版，本包不夹带开发者收集的二进制表单。

这几个模块可以按需接入；没有依赖时报告缺项，不擅自安装整套私人基础设施，也不自动把材料上传到外部OCR或AI服务。
