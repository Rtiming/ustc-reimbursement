# 报销执行模式

用户要求“全权限模式”“完全权限模式”或明确允许本次报销自主切换界面时，启用`full_control`。用户指定的本案或批次内持续有效，接续和恢复不重复询问。未指定模式时保留`silent`默认；不把单案授权扩成其他案件或全局默认。

## 全权限执行

在当前用户任务范围内，自主完成界面/标签/窗口切换、已有登录恢复、材料读取归档、参数准备、填单保存、导出和工具修复。需要前台时可直接激活财务页；新开页可传`silent=false`。继续使用正式报销工具，不另开任意JS、URL或坐标操作通道。

用户同时要求完整“提交报销”时，对本案已核定范围登记提交、普通承诺及必要的本人申请人确认授权，推进到提交完成，不逐步重复问许可。用户限定“只做草稿”或“到本人确认前”时按该停点执行；验证码出现时保留现场交本人完成。其他证明人、经费负责人及财务审批仍由相应人员办理。

模式不解决事实缺口。金额、收款身份、预算范围不明的那一项留待确认，其他已核清项继续；不能凭“全权限”填造追加审批、手机号、付款凭证或把他人票据解除占用。已发生的未知写入仍只恢复原请求并独立回读，不换请求号重放。

## 在工具中登记

通过现有`overview → update_case(document="case")`登记`material_context.execution_mode`，保留其他资料：

```json
{
  "schema": "ustc-execution-mode-v1",
  "mode": "full_control",
  "case_id": "当前案件",
  "authorized_by": "user",
  "source": "本次用户直接授权记录及SHA",
  "restore_context": true
}
```

任务层读取本案模式。AppleEvent后端在执行已明确财务标签的任务前，按授权激活它；已在目标页则跳过激活。Native Messaging继续使用其后台能力，不因模式而换连接或命名空间。材料任务、预览计划和本地结果登记不激活浏览器。执行前检查已观察的原生接口状态；401/403/404时记录业务命令尚未派发，沿正式登录恢复后核原单，不能把缓存姓名当作有效连接。模式只改变界面准备，不代替原有业务校验、提交计划和保存回读。

登记批次在执行财务阶段前，将同源模式登记到正式索引里的子案；已有显式模式的子案保留自身设置。只做status或预览时不修改参数。overview会显示当前模式；详细用法可查guide(topic="execution")。

一次办理结束用`access(action="restore-context", execute=true)`恢复本案记录的原标签和前台；用户中途改到其他标签/应用时保留用户选择。多个案件按激活的逆序收尾。验证码或本人输入尚未完成时保留必要现场。用户要求停留财务页可登记`restore_context=false`；撤销全权限时先恢复现场，再将同案mode改为`silent`。

完整记录在本机`.local/finance_execution/<case_id>/`及任务`execution-mode.json`中，不随材料跨设备复制。换设备重新核对原生标签，业务授权仍引用同案记录。工具未支持的页面/后端明确列出缺口，不能把离线测试说成现场验收。
